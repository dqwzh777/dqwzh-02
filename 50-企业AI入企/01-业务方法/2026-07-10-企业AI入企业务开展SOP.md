# 企业 AI（人工智能）入企业务开展 SOP（标准作业流程）

## 一、流程目的

这套流程用于指导老王及团队，从找到潜在客户开始，到完成企业诊断、小范围试点、项目验收、案例沉淀和后续复制。

核心原则：

> 不先卖工具，先看经营问题；不先全面改造，先做一个试点；不空口承诺效果，先记录数据，再用结果说话。

完整业务闭环：

> 内容与公开课获客 → 客户初筛 → 首次沟通 → 企业诊断 → 试点方案 → 报价签约 → 项目启动 → 流程拆解 → 资料整理 → 工作流搭建 → 员工实操 → 陪跑复盘 → 效果验收 → 案例沉淀 → 扩展续费。

---

## 二、业务定位与服务边界

### 1. 一句话定位

> 老王帮助传统企业从一个真实岗位切入，先找到低效流程，再用小试点跑通一条可重复、可衡量的 AI（人工智能）工作流，最后根据数据决定是否扩大应用。

### 2. 当前核心产品

1. 企业 AI（人工智能）场景诊断。
2. 单岗位或单流程试点。
3. 企业 AI（人工智能）落地陪跑。
4. 已验证工作流的部门复制。
5. 企业知识资料整理与内部能力建设。

### 3. 当前不优先做的项目

- 只要求介绍大量工具、没有业务目标的培训。
- 一开始就要求全面改造整家企业的项目。
- 没有内部负责人，却要求外部团队对结果全权负责的项目。
- 不提供任何真实资料，却要求直接搭建业务系统的项目。
- 要求承诺一定裁员、一定提高收入或保证具体效果的项目。
- 涉及高风险业务，但客户不接受人工审核和安全规范的项目。

## 三、业务阶段总表

| 阶段 | 核心动作 | 必须产出 | 是否继续的判断 |
|---|---|---|---|
| 1. 获客 | 内容、公开课、转介绍 | 潜在客户名单 | 是否出现真实企业问题 |
| 2. 初筛 | 基础信息与合作条件判断 | 客户初筛表 | 是否值得进入访谈 |
| 3. 首次沟通 | 理解经营问题与决策动机 | 首次沟通记录 | 是否有明确问题和负责人 |
| 4. 付费诊断 | 访谈、流程梳理、场景评分 | 机会清单与试点路线图 | 是否存在合适的试点 |
| 5. 方案签约 | 明确目标、边界、周期和费用 | 试点方案、合同、回款 | 是否具备启动条件 |
| 6. 项目实施 | 资料、流程、工具、员工训练 | 可运行工作流 | 员工能否真实使用 |
| 7. 陪跑验收 | 记录数据、修正问题 | 验收与复盘报告 | 是否达到约定标准 |
| 8. 案例沉淀 | 脱敏整理过程和结果 | 标准案例卡 | 是否获得授权和证据 |
| 9. 扩展续费 | 复制到相邻岗位 | 二期路线图 | 是否值得扩大应用 |

## 四、第一阶段：获客与线索进入

### 目标

让传统企业老板理解：员工会用 AI（人工智能）工具，不等于企业真正形成了提效流程。

### 主要获客渠道

- 老板朋友圈和私域内容。
- 短视频和图文内容。
- 面向企业老板的公开课。
- 商协会、园区和企业家活动。
- 老客户、朋友与合作伙伴转介绍。
- 本地企业拜访。

### 内容重点

围绕老板的决策问题，而不是天天介绍新工具：

1. 企业应该从哪个岗位开始？
2. 为什么培训结束后员工不用？
3. 怎样判断一个场景值不值得改造？
4. 如何记录改造前后的效果？
5. 什么任务不适合直接交给 AI（人工智能）？
6. 为什么要先做小试点？

### 统一承接动作

所有内容尽量只承接一个下一步：

> 预约一次企业 AI（人工智能）场景初步沟通，先判断企业适不适合做、应该从哪里开始。

### 线索登记字段

- 企业名称。
- 联系人及职务。
- 行业与规模。
- 线索来源。
- 当前最想解决的问题。
- 目前是否使用 AI（人工智能）。
- 是否有明确决策人。
- 下次联系时间。
- 当前状态。

## 五、第二阶段：客户初筛

### 目标

在投入深度诊断时间之前，判断客户是否具备合作基础。

### 必问八个问题

1. 企业目前最想改善的是成本、效率、收入、管理还是风险？
2. 哪个部门或岗位的问题最明显？
3. 这个问题多久发生一次？
4. 目前由多少人、用多少时间处理？
5. 企业以前尝试过什么解决办法？
6. 谁负责推动这次项目？
7. 企业是否愿意提供脱敏后的真实资料？
8. 企业是否愿意记录试点前后的数据？

### 合格客户条件

- 老板或核心管理者支持。
- 有一个相对具体的业务问题。
- 有高频、重复或资料密集型任务。
- 愿意指定一位内部负责人。
- 愿意让真实员工参与。
- 愿意提供必要资料。
- 愿意接受先试点再扩大的方式。
- 对结果的期待基本合理。

### 暂缓条件

- 只想听概念，不准备采取行动。
- 只想询价，却不愿说明任何业务问题。
- 要求马上替代大量员工。
- 没有负责人，也没有员工配合。
- 不允许接触任何资料。
- 要求在没有基准数据的情况下保证效果。

### 阶段产出

- 《潜在客户初筛表》。
- 客户状态：合格、待培育、暂不适合。
- 下一步：预约首次深度沟通或进入内容培育。

## 六、第三阶段：首次深度沟通

### 目标

不是急着介绍服务，而是确认问题是否真实、是否值得付费解决。

### 沟通顺序

#### 1. 先了解企业

- 企业主要业务是什么？
- 主要客户是谁？
- 当前哪个部门最忙、最缺人或最容易出错？
- 老板为什么现在开始关注 AI（人工智能）？

#### 2. 再还原问题

- 请客户讲一个最近真实发生的例子。
- 这个任务从谁开始，到谁结束？
- 中间经过哪些步骤？
- 哪一步最慢、最贵、最容易错？
- 如果不改变，未来会造成什么影响？

#### 3. 再判断决策条件

- 谁最终拍板？
- 谁负责配合？
- 希望什么时候看到结果？
- 能否接受从一个小场景开始？
- 如何判断项目做得好不好？

### 沟通结束时的三种处理

1. **适合诊断**：说明付费诊断的范围、交付物和下一步。
2. **暂时不成熟**：告知缺少的条件，进入后续培育。
3. **明显不适合**：明确说明原因，不勉强成交。

### 禁止动作

- 第一次沟通就承诺具体节省人数。
- 没有看流程就推荐工具。
- 为了成交，答应超出能力和资源范围的项目。
- 免费完成完整诊断和方案设计。

## 七、第四阶段：企业 AI（人工智能）场景诊断

### 目标

把“我们想做人工智能”变成一张有优先级的业务机会清单。

### 诊断对象

- 企业负责人。
- 部门负责人。
- 实际执行任务的一线员工。
- 必要时包括信息、安全或财务负责人。

### 诊断步骤

1. 确认企业经营目标。
2. 选择一到三个重点部门。
3. 列出部门主要岗位。
4. 列出岗位高频任务。
5. 让员工现场演示真实工作过程。
6. 记录任务输入、步骤、判断和输出。
7. 记录耗时、频率、人员和常见错误。
8. 检查现有资料、模板和历史案例。
9. 判断数据与安全风险。
10. 对候选场景进行评分和排序。

### 场景评分维度

每个维度可按一到五分记录：

- 发生频率。
- 人工耗时。
- 重复程度。
- 规则清晰程度。
- 资料完整程度。
- 结果可检查程度。
- 业务价值。
- 员工配合度。
- 实施难度。
- 出错风险。

优先选择：

> 高频、高耗时、高重复、规则较清晰、资料较完整、结果可检查、风险可控的场景。

### 诊断交付物

1. 《企业 AI（人工智能）机会清单》。
2. 《岗位任务与痛点地图》。
3. 《候选场景评分表》。
4. 《首个试点建议书》。
5. 《暂不建议实施的场景及原因》。

### 诊断结束判断

只有满足以下条件，才进入试点报价：

- 场景足够具体。
- 有明确输入和输出。
- 有负责人和真实使用员工。
- 有基本资料或可以在项目期内补齐。
- 能记录改造前后的数据。
- 风险处于可控制范围。

## 八、第五阶段：试点方案、报价与签约

### 试点方案必须写清

- 项目背景。
- 具体岗位和任务。
- 当前流程与问题。
- 本次试点目标。
- 项目范围。
- 不在本次范围内的事项。
- 双方负责人。
- 企业需要提供的资料。
- 实施步骤与时间安排。
- 具体交付物。
- 员工培训与陪跑安排。
- 效果记录和验收方式。
- 数据安全与保密要求。
- 费用、付款节点和变更规则。

### 定价原则

在缺少真实成交数据之前，不把价格拍死。报价至少考虑：

- 诊断与访谈工作量。
- 涉及岗位和人员数量。
- 资料整理难度。
- 工具和系统复杂度。
- 培训和陪跑周期。
- 是否需要现场服务。
- 数据风险和责任成本。
- 后续维护范围。

### 启动前硬门槛

- 合同已确认。
- 首期款已到账。
- 双方负责人已确定。
- 项目范围已书面确认。
- 企业资料清单已发送。
- 首次启动会议已排期。

未满足以上条件，不正式启动实施。

## 九、第六阶段：项目启动与基准数据记录

### 启动会议议程

1. 重新确认试点目标。
2. 确认岗位、任务和使用员工。
3. 明确双方分工。
4. 确认资料提供时间。
5. 确认培训和复盘时间。
6. 说明安全和保密边界。
7. 说明效果如何记录和验收。
8. 建立项目沟通群和问题反馈方式。

### 必须先记录的基准数据

- 单次任务平均耗时。
- 每天或每周发生次数。
- 参与人数。
- 返工次数。
- 常见错误类型。
- 响应时间。
- 当前输出质量。
- 员工当前操作步骤。

没有基准数据，就不能在项目结束时准确证明效果。

### 阶段产出

- 《项目启动确认单》。
- 《双方责任清单》。
- 《资料需求清单》。
- 《改造前基准数据表》。
- 《项目排期表》。

## 十、第七阶段：流程拆解与资料整理

### 流程拆解方法

让员工完成一次真实任务，并记录：

1. 任务如何触发。
2. 需要哪些输入信息。
3. 去哪里查资料。
4. 经过哪些人工步骤。
5. 哪些地方需要判断。
6. 由谁审核。
7. 最终以什么格式输出。
8. 出错以后如何处理。

### 资料整理范围

- 企业介绍。
- 产品与服务资料。
- 标准话术。
- 常见问题。
- 历史优秀案例。
- 表格和输出模板。
- 业务规则。
- 禁止表达。
- 审核标准。
- 权限和保密要求。

### 资料处理原则

- 先脱敏，再使用。
- 来源不清楚的资料不直接采用。
- 过期资料先确认。
- 不把员工个人经验当成企业统一标准。
- 关键业务事实必须由企业负责人确认。

### 阶段产出

- 《改造前流程图》。
- 《业务资料目录》。
- 《知识缺口清单》。
- 《人工智能可介入步骤清单》。
- 《必须人工处理步骤清单》。

## 十一、第八阶段：工作流搭建与内部测试

### 搭建原则

- 先做最短可运行流程。
- 先保证稳定，再增加自动化。
- 重要事实必须保留人工核对。
- 高风险输出必须经过负责人审核。
- 每个步骤都要说明输入、动作、输出和责任人。

### 基础工作流结构

> 员工输入真实任务 → AI（人工智能）调用指定资料 → 生成初步结果 → 员工核对关键事实 → 按企业模板输出 → 负责人抽查 → 问题回流优化。

### 内部测试要求

- 使用不少于三种不同类型的真实任务测试。
- 测试正常情况和异常情况。
- 检查事实错误、遗漏、格式和语气。
- 记录每一次失败原因。
- 不用只展示最成功的一次结果。

### 上线前检查

- [ ] 输入要求清楚。
- [ ] 输出模板固定。
- [ ] 资料来源可追溯。
- [ ] 人工审核节点明确。
- [ ] 错误处理方式明确。
- [ ] 安全边界明确。
- [ ] 使用员工能够访问相关工具。

## 十二、第九阶段：员工培训与真实任务实操

### 培训目标

不是让员工听懂，而是让员工能独立完成真实任务。

### 培训流程

1. 解释项目为什么做。
2. 说明工作流解决哪项工作问题。
3. 演示一次真实任务。
4. 让员工自己操作。
5. 记录员工卡住的地方。
6. 当场修正流程和说明。
7. 再让员工独立完成一次。
8. 说明错误上报和反馈方式。

### 培训验收

员工需要做到：

- 知道什么任务可以使用。
- 知道怎样准备输入资料。
- 能独立完成操作。
- 能识别明显错误。
- 知道哪些内容必须人工确认。
- 知道哪些数据不能上传。
- 知道遇到问题找谁。

### 培训产出

- 《岗位操作手册》。
- 《员工练习任务》。
- 《常见问题清单》。
- 《安全使用规范》。
- 培训签到和实操记录。

---

## 十三、第十阶段：陪跑、问题处理与版本更新

### 建议陪跑节奏

- 上线第一周：高频反馈，及时解决使用障碍。
- 第二周：观察员工是否持续使用，修正流程问题。
- 第三周：对比输出质量和效率，补充资料。
- 第四周：汇总数据，准备验收和复盘。

实际周期根据项目复杂度在方案中确定。

### 每次复盘必问

1. 本周真实使用了多少次？
2. 哪类任务效果最好？
3. 哪类任务最容易出错？
4. 员工为什么不用或少用？
5. 是工具问题、资料问题、流程问题还是人员问题？
6. 哪些修改已经验证有效？
7. 下周只优先解决哪个问题？

### 问题分类

- 工具问题。
- 资料问题。
- 流程问题。
- 权限问题。
- 员工操作问题。
- 管理推动问题。
- 需求超出原范围。

超出原范围的新需求，先记录、评估和报价，不直接无限增加交付内容。

## 十四、第十一阶段：效果验收

### 验收指标

根据项目选择，不要求每项都用：

| 指标 | 改造前 | 改造后 | 变化 | 证据来源 |

| 返工次数 |  |  |  |  |
| 错误数量 |  |  |  |  |
| 响应速度 |  |  |  |  |
| 输出质量 |  |  |  |  |
| 员工使用率 |  |  |  |  |

### 验收会议

1. 回顾原始问题。
2. 展示改造前流程。
3. 展示新的工作流。
4. 对比项目数据。
5. 说明已经解决的问题。
6. 说明仍未解决的问题。
7. 收集员工和负责人反馈。
8. 给出是否适合继续扩大的建议。

### 结果表达边界

- 可以证明某项任务节省时间，不等于可以直接裁减人员。
- 可以证明输出速度提高，不等于保证企业收入增长。
- 数据不足时，明确写“当前样本不足”。
- 没达到目标时，说明原因和后续建议，不隐瞒。

### 验收产出

- 《改造前后数据对比表》。
- 《项目验收报告》。
- 《员工反馈记录》。
- 《下一阶段建议书》。

## 十五、第十二阶段：案例沉淀

### 案例结构

1. 客户行业与基本情况。
2. 原来的业务问题。
3. 原工作流程。
4. 为什么选择这个试点。
5. 实施了哪些动作。
6. 员工如何真实使用。
7. 遇到哪些问题。
8. 如何调整。
9. 改造前后数据。
10. 员工和老板反馈。
11. 尚未解决的问题。
12. 后续扩展方向。

### 证据清单

- 改造前后流程图。
- 交付物截图。
- 员工实操记录。
- 数据记录表。
- 客户原话。
- 项目复盘记录。
- 客户授权说明。

### 脱敏要求

- 未经客户书面同意，不公开企业名称和敏感信息。
- 客户资料、人员信息和经营数据必须脱敏。
- 对外公布的数据必须能够追溯来源。
- 不为了宣传夸大结果。

---

## 十六、第十三阶段：扩展、续费与长期陪跑

### 扩展顺序

优先从已经跑通的流程向相邻任务复制：

> 同一岗位的其他任务 → 同一部门的其他岗位 → 相邻部门 → 企业级知识和流程体系。

### 续费判断条件

- 首个流程已经稳定使用。
- 有可以确认的效果或明确的改进价值。
- 企业内部负责人愿意继续推动。
- 还有相似、高价值场景。
- 企业愿意继续提供资料和人员配合。

### 二期方案内容

- 第一期结果总结。
- 新候选场景清单。
- 优先级和预期价值。
- 新项目范围。
- 人员和资料要求。
- 实施周期。
- 新的验收指标。

## 十七、团队职责

早期可以一人承担多个角色，但每项职责必须有人负责。

| 角色 | 主要职责 |
|---|---|
| 老王或商务负责人 | 获客、筛选、沟通、控制承诺、推动签约 |
| 业务诊断负责人 | 访谈、流程还原、场景判断、验收指标设计 |
| 实施负责人 | 资料整理、工具配置、工作流搭建和测试 |
| 培训陪跑负责人 | 员工实操、问题收集、使用推动和复盘 |
| 项目负责人 | 排期、沟通、变更控制、风险和交付物管理 |

- 项目最常见的交付问题。

## 二十、首批项目执行重点

当前还没有正式客户，第一阶段的目标不是立即扩大规模，而是跑通一个完整闭环。

### 第一批客户策略

- 优先从熟人、老关系和本地企业中寻找。
- 先完成三到五次真实访谈。
- 从中筛选一到两个合适的小试点。
- 正式实施原则上收费。
- 如果提供特殊合作价格，必须换取数据记录、深度配合和案例授权。
- 第一批项目不要同时跨太多行业和岗位。

### 第一个案例必须留下的资产

1. 客户初筛表。
2. 首次沟通记录。
3. 企业诊断报告。
4. 场景评分表。
5. 试点方案和合同。
6. 改造前数据。
7. 流程图和资料目录。
8. 工作流和操作手册。
9. 员工实操记录。
10. 改造后数据。
11. 验收报告。
12. 脱敏案例卡。

# AI 内容获客系统搭建：课程拆解与落地手册

> 课程：07-05 实操培训：AI 内容获客系统搭建、知识库运营及 Agent 落地全流程  
> 讲者：樊静（三金）  
> 时长：约 51 分钟  
> 类型：课程学习笔记 / 系统拆解  
> 来源：PLAUD 录音逐字稿  
> 整理日期：2026-07-10

---

## 一句话结论

这门课真正讲的不是“让 AI 写爆款”，而是把老板或创作者每天产生的录音、客户问题、案例和经验，持续加工成**可检索的业务知识、可复用的工作流程和可发布的内容**。

它的核心竞争力不是某个模型，而是一个持续循环：

> 业务输入 → AI 整理 → 知识入库 → 选题与创作 → 人工审核 → 发布 → 数据复盘 → 更新规则

最值得学的不是工具清单，而是三个系统设计：

1. 每次输入都要沉淀，避免一次性消费。
2. 每次人工修改都要反向更新规则，让系统逐渐像自己。
3. 重复劳动可以自动化，但选题、观点和发布判断应先保留人工决策。

## 一、课程的核心问题

传统内容生产有五类浪费：

- 客户聊了一两个小时，只记住一两个问题，其余需求丢失。
- 会议纪要和课程笔记虽然保存了，却很少再次使用。
- 老板的产品经验和案例都在脑子里，员工无法准确表达。
- 每次使用 ChatGPT 等工具都从头解释背景，对话结束后没有沉淀。
- AI 生成的稿件每次都要改，但修改经验没有回写，下次继续犯同样的问题。

课程提出的解法是：建立一个以本地知识库为核心的内容复利系统，让资料不仅被“保存”，还能够被调用、更新和淘汰。

## 二、完整系统地图

### 1. 五步内容复利闭环

| 环节 | 输入或动作 | 产出 | 关键控制点 |
|---|---|---|---|
| 输入 | 客户录音、会议、课程、聊天、灵感、外部文章 | 原始语料 | 尽量自动采集 |
| 处理 | 转写、提取、分类、去重 | 结构化知识 | 保留来源与应用 |
| 调用 | 从知识库取产品、客户、案例、方法 | 内容初稿 | 选题由人拍板 |
| 分发 | 朋友圈、公众号、小红书、口播等 | 平台内容 | 发布前诊断与审核 |
| 复盘 | 曝光、点击、点赞、收藏、评论、咨询 | 新的方法和规则 | 将有效标题、开头等回写 |

闭环每运行一轮，知识库和工作规则都会增加一点；这才是课程所说的“复利”。

### 2. 系统的四层架构

| 层级 | 作用 | 课程中的工具示例 |
|---|---|---|
| 交互入口 | 手机发指令、接收结果、做决策 | 飞书机器人 |
| 调度层 | 把消息转成任务并选择执行流程 | 课程提及 Homer/Holmes，转写名称不确定 |
| 执行层 | 读取文件并按固定 SOP 工作 | Claude Code / Codex + Skills |
| 知识层 | 存放可读、可链接、可同步的业务资料 | Obsidian 本地库 |

讲师的关键判断是：**入口不是大脑，模型也不是资产；本地知识与固定流程才是大脑和资产。**

### 3. 为什么课程选择 Obsidian

课程给出的理由：

- 文件本地化，编码型 AI 可以直接读取和修改。
- Markdown 结构简单，便于人和 AI 同时使用。
- 支持链接、标签和可视化浏览。
- 可以通过 iCloud 或官方同步打通手机和电脑。
- 相比只能“基于资料问答”的知识库，它允许 AI 主动补充和维护文件。

更准确的理解是：不是 Obsidian 本身创造了能力，而是**本地 Markdown 文件 + 可操作文件的 AI**形成了低摩擦组合。Obsidian只是一个适合人类查看和维护的界面。

## 三、六大核心知识库

| 知识库 | 核心问题 | 应放内容 |
|---|---|---|
| 老板与企业说明书 | 我是谁、相信什么、如何表达 | 身份、经历、价值观、语言风格、禁区 |
| 产品服务库 | 我卖什么、为什么值得买 | 产品、价格、卖点、交付、异议处理 |
| 客户需求库 | 客户真正关心什么 | 客户原话、问题、场景、顾虑、搜索词 |
| 案例与证据库 | 凭什么相信我 | 客户案例、前后对比、数据、故事、素材 |
| 方法与 SOP 库 | 我是怎么做成的 | 框架、步骤、判断标准、检查清单 |
| 内容与承接库 | 接下来写什么、如何转化 | 选题、平台内容、标题、承接路径、数据复盘 |

### 建库原则

1. 先建立通用六库，再通过业务体检增加垂直库。
2. 按“主题”组织，而不是按“哪本书、哪个老师、哪个来源”组织。
3. 每篇资料必须标注：
   - 来源：这条信息从哪里来。
   - 应用：它未来在哪个任务中被调用。
4. 与业务定位无关的内容不必入库，避免知识库无限膨胀。

### 推荐的笔记元数据

```yaml
---
title: 客户为什么迟迟不下单
type: 客户问题
topic: 销售转化
source: 2026-07-05 客户咨询录音
applications:
  - 朋友圈文案
  - 销售答疑
  - 小红书搜索笔记
status: active
use_count: 0
---
```

## 四、知识库如何“有生命”

### 机制 1：按主题分类，而不是按来源分类

错误示例：

- 《某某书》笔记
- 某老师课程
- 某公众号文章

这种分类便于人回忆来源，却不利于 AI 执行任务。AI 写销售内容时需要的是“销售方法”，并不关心它来自哪位老师。

更好的分类：

- 内容创作
- 销售与成交
- 搜索与 SEO
- 运营管理
- 产品与交付
- 财税合规

来源信息放入文档元数据，而不是作为顶层目录。

### 机制 2：来源 + 应用双标签

- 来源解决可信度、追溯和版权边界问题。
- 应用解决 AI 在什么任务中应该调用的问题。

“应用”实际上是在为未来的 AI 建立路由规则，比普通主题标签更有价值。

### 机制 3：素材三次封顶

课程设计：优先使用与定位最匹配的素材；每使用一次就记录一次；达到三次后移入“已过时素材”，默认不再调用。

它解决的是 AI 偷懒和内容重复，但“三次”不是普遍真理。更合理的做法是按素材类型设置策略：

- 核心品牌故事：可以重复，但需要换角度。
- 客户案例：限制同平台、同周期的重复次数。
- 数据和政策：按有效期淘汰。
- 表达金句：可复用，但应控制相邻内容重复。

### 机制 4：定期知识库体检

让 AI 对照当前业务、客户和产品检查：

- 哪些库已经比较完整？
- 哪些关键证据缺失？
- 哪些客户问题没有答案？
- 哪些方法只有观点，没有 SOP？
- 哪些文件长期未使用或已经过时？
- 是否需要增加垂直业务库？

体检结果应先由人确认，再创建目录或批量迁移，避免 AI 自行扩张结构。

## 五、录音处理：把业务现场变成资产

### 六要素提取法

| 要素 | 提取内容 | 去向 |
|---|---|---|
| A. 认知 | 新观点、新判断、新发现 | 方法库 / 案例库 |
| B. 方法论 | 可复用框架、步骤、判断标准 | 方法 SOP 库 |
| C. 故事与数据 | 经历、数字、客户案例、踩坑 | 案例证据库 |
| D. 情绪表达 | 焦虑、兴奋、冲突和有感染力的原话 | 案例库 / 写作素材 |
| E. 选题 | 可展开成内容的角度 | 内容与承接库 |
| F. 待办 | 明确动作、联系人、截止事项 | Todo 系统 |

### 标准处理流程

1. 录制客户对话、会议、课程或个人语音。
2. 转成逐字稿，放入“待处理录音”。
3. AI 必须先通读全文，再进行提取，不能边读边分流。
4. 输出六要素整理稿。
5. 人工确认保留、删除和敏感信息处理。
6. 将条目写入对应知识库，并标注来源与应用。
7. 从新增素材中推荐选题和下一步任务。

### 课程案例：旗袍定制

问题：老板知道客户需求、定制过程和款式卖点，但员工不知道；员工写的小红书只能罗列款式和材质。

改造后：

- 客户沟通被录音并结构化。
- 客户画像、需求、定制过程、产品卖点进入知识库。
- 员工写内容时，AI 自动调用真实案例和卖点。
- 内容从“产品说明”变成“特定客户问题的解决方案”。

课程称这类笔记点赞不一定很高，但持续产生私信咨询。这个案例提示：**获客内容的评价指标不应只看点赞，更要看有效咨询和成交。**

## 六、Skill：把重复工作固化成 SOP

### Skill 的本质

Skill 不是神秘的智能体，而是一份 AI 可执行的流程说明：

- 它做什么？
- 在什么条件下触发？
- 分几步完成？
- 每步读取什么资料？
- 用什么判断标准？
- 输出到哪里？
- 哪一步必须让人确认？

### 创建 Skill 的三种路径

1. 先人工与 AI 完整跑通一次流程，再让 AI 将过程固化。
2. 没有现成流程时，描述需求，让 AI 搜索并评估开源 Skill。
3. 发现新 Skill 时，不直接替换；先比较现有版本与新版本，再决定采用、融合或借鉴。

### 内容生产 Skill 矩阵

| 阶段 | 典型 Skill |
|---|---|
| 输入处理 | 录音处理、对话整理、外部文章拆解 |
| 选题挖掘 | 客户问题挖掘、评论区需求、对标内容拆解 |
| 内容生产 | 朋友圈、公众号、小红书、搜索笔记、口播稿 |
| 内容诊断 | 开头优化、逻辑检查、违规检查、标题生成 |
| 战略与产品 | 定位诊断、产品分析、知识库采访 |
| 建库维护 | 归档、去重、体检、过期素材维护 |

### 把 Skills 连成一张网

在每个 Skill 结束时给出“推荐下一步”，例如：

- 录音处理完成 → 写朋友圈 / 写公众号 / 提取产品洞察。
- 选题挖掘完成 → 做需求验证 / 生成结构。
- 初稿完成 → 内容诊断 / 标题生成 / 人工审核。
- 发布完成 → 记录数据 / 定期复盘。

这样，人不需要记住二十多个 Skill 的名称，只需要根据当前结果选择下一步。

## 七、三个高价值设计

### 1. Big 10 对标标题库

方法：选择 10 个业务相关但标题风格差异较大的账号，提炼各自的标题风格；每篇内容完成后，按这些风格生成 10—20 个候选标题。

价值：降低标题创作的偶然性，扩大候选空间。

风险：只模仿标题表面会产生同质化或标题党。应增加三项检查：

- 标题承诺是否被正文兑现？
- 是否符合自己的品牌定位？
- 是否记录实际点击率并淘汰无效风格？

### 2. 修改稿反向沉淀

每次人工修改 AI 初稿后，让 AI 对比初稿与终稿：

1. 改了哪些内容？
2. 为什么改？
3. 体现了什么表达偏好或判断规则？
4. 哪些规则应加入写作 Skill？

课程中的例子是：讲师不喜欢制造焦虑，更偏好平和表达、增加个人案例和更完整的解释。把这些修改沉淀后，后续初稿会更接近她的风格。

这是整门课最重要的方法之一：**修改不是返工，而是训练数据。**

### 3. 从历史作品提炼表达风格

把过往最能代表自己的朋友圈、公众号、小红书内容整理给 AI，让它：

- 聚类成若干表达模式。
- 为每种模式总结结构、语气、开头、节奏、案例使用和禁区。
- 根据不同主题选择适合的风格。

讲师自述曾用 5,553 篇朋友圈提炼出 6 种风格。这个数字是个人案例，不是最低要求；实际可以先用 30—100 篇高质量代表作完成第一版。

## 八、从 Skill 升级为 Agent

课程对 Agent 的实用定义是：

> 给已有 Skill 增加一个入口、触发条件、资料来源、执行边界和结果回传方式，使其无需每次手动打开工作台也能运行。

### Agent 五要素

1. 触发方式：一句指令、事件触发，还是定时触发？
2. 数据来源：飞书录音、Obsidian、本地目录，还是平台数据？
3. 执行 Skill：调用哪个固定流程？
4. 结果去向：保存到哪里、通知到哪里？
5. 决策节点：哪一步必须由人确认？

### 适合自动化的任务

- 每天定时整理前一天的录音。
- 会议纪要和任务提取。
- 对标账号与关键词的定期监控。
- 平台数据汇总。
- 内容初稿的格式检查、敏感词检查和归档。

### 不宜一开始全自动的任务

- 判断哪个观点值得公开表达。
- 决定内容是否符合个人价值观。
- 未经审核自动发布。
- 高风险行业的事实、法律、医疗或投资判断。
- 涉及客户隐私的自动入库与分发。

正确路线应是：手动跑通 → 半自动 → 持续回写规则 → 低风险环节全自动。

## 九、对课程观点的审视

### 1. 真正成立的部分

- 模型会变化，自己的业务资料和 SOP 更具有长期价值。
- 录音、客户问题和修改记录是高质量的第一方数据。
- 本地 Markdown 知识库便于迁移，能降低单一平台锁定风险。
- 人机分工应是 AI 处理重复劳动，人负责价值判断和最终发布。
- 内容获客不能只看曝光，咨询质量、线索和成交更接近业务目标。

### 2. 需要保留判断的部分

- “一份输入产生无限价值”是方向性表达；低质量输入不会自动变成高质量资产。
- 知识库越大不一定越好。没有检索规则、版本控制和淘汰机制时，大库会增加噪声。
- AI 自动分类仍可能错放、重复和错误推断，重要业务知识必须抽查。
- 三次封顶是启发式规则，不能机械应用于所有素材。
- 自动监控和平台采集受平台规则、登录权限、接口稳定性及合规要求限制。
- 课程涉及的部分工具名在转写中失真，如“飞书 CRI/CPI”“Homer/Holmes”“扣带斯”等，安装时应以原讲义和官方名称为准。

### 3. 课程没有充分展开的风险

- 客户录音应获得必要授权，并在入库前去除手机号、地址、合同和其他敏感信息。
- 付费课程和他人文章可以用于个人学习，但不等于可以重发布或商业化复制。
- AI 可能编造来源、错误归纳或把个案概括成普遍规律。
- 自动发布一旦出错会扩大品牌与合规风险，应设置审批闸门和操作日志。
- 知识库需要备份、权限控制和版本管理，否则自动改写可能破坏原始资料。

## 十、最小可行版本：先用 7 天跑通

不要一开始就搭二十多个 Skill 和多个 Agent。第一版只需要：

- 一个本地 Obsidian 知识库。
- 六个核心目录。
- 一个录音处理 Skill。
- 一个常用平台的内容生成 Skill。
- 一个内容诊断 Skill。
- 一个“人工确认后发布”的审批节点。

### 第 1 天：搭骨架

- [ ] 建立六大知识库。
- [ ] 写一页老板与企业说明书。
- [ ] 写清一个核心产品和一个目标客户。

### 第 2 天：准备真实素材

- [ ] 选一段 10—30 分钟的客户或业务录音。
- [ ] 转写并去除敏感信息。
- [ ] 用六要素处理并保留原文链接。

### 第 3 天：完成第一次入库

- [ ] 将观点、方法、案例、问题和选题分别入库。
- [ ] 每条补齐来源与应用。
- [ ] 人工抽查分类是否正确。

### 第 4 天：从素材生成一篇内容

- [ ] 从新增选题中只选一个。
- [ ] 先确认结构，再写正文。
- [ ] 跑一遍事实、逻辑、平台风险和标题检查。

### 第 5 天：反向沉淀修改

- [ ] 人工修改初稿。
- [ ] 对比初稿和终稿。
- [ ] 把稳定偏好写回写作规则。

### 第 6 天：发布并记录业务数据

- [ ] 发布到一个主平台。
- [ ] 记录曝光、点击、互动、咨询、有效线索。
- [ ] 不只用点赞评价内容。

### 第 7 天：复盘

- [ ] 哪一步最耗时？
- [ ] 哪一步最容易出错？
- [ ] 哪一步重复且判断标准明确？
- [ ] 只把这一环节自动化。

## 十一、可直接复用的执行模板

### 录音处理指令

```text
请先通读完整逐字稿，不要边读边整理。

完成后按以下六类提取：
1. 认知与观点
2. 可复用方法论
3. 故事、案例与数据
4. 有感染力的原话和情绪表达
5. 可发展的内容选题
6. 明确待办

要求：
- 忽略闲聊和重复；
- 保留数字、时间和案例细节；
- 不确定的信息标注“待核实”；
- 每条标明原文时间点；
- 先给出待入库清单，等我确认后再写入知识库。
```

## 十二、6 要素提取

### A. 认知 / 观点

- 内容获客的核心不是爆款技巧，而是个人经验持续产生复利的系统。
- 模型可替换，业务上下文、知识库和流程更接近长期资产。
- AI 获得足够的产品、客户、案例和方法上下文后，才可能像业务助理。
- 与 AI 的对话和人工改稿也应回收为资产，而不是一次性消费。
- 自动化的价值是消灭重复劳动，而不是取消人的判断。

### B. 方法论

- 输入—处理—调用—分发—复盘五步闭环。
- 六大业务知识库。
- 录音六要素提取法。
- 主题分类 + 来源/应用双标签。
- 素材使用计数与过期机制。
- Skill 结束后推荐下一步，形成流程网络。
- 初稿与终稿对比，反向更新写作规则。
- Agent 五要素：触发、来源、Skill、回传、决策。

### C. 故事 / 数据

- 讲师自述有 6 年小红书实战经验。
- 旗袍定制案例：将老板脑中的客户需求和产品卖点转成知识库，员工内容开始出现真实案例与结构化卖点，并持续产生私信咨询。
- 讲师自述用 5,553 篇朋友圈内容提炼出 6 种表达风格。
- 素材采用“三次封顶”规则，达到三次后进入已过时素材区。
- 讲师自述系统成熟后每天工作约 4—5 小时；这是个人经验，不能直接视为普遍结果。

### D. 关键原话

- “获客的本质其实不是教你写爆款。”
- “只有 AI 拿着你的经验，拿着你的客户案例，拿着你做事情的方法论的时候，它才能真正像你的助理一样。”
- “每一次改稿子，都在给整个系统打补丁。”
- “重复的活儿交给 AI，关键的判断永远还是我们自己来。”

### E. 可发展的选题

- 为什么老板的知识库必须围绕客户问题，而不是围绕文件来源？
- AI 写作一直不像你，问题可能不在提示词，而在修改没有回写。
- 企业用 AI 最容易犯的错：先追模型，后补业务上下文。
- 录音不是会议记录，而是最容易被浪费的第一方业务数据。
- 为什么内容自动发布越快，品牌风险可能越大？
- 点赞不高却持续带来咨询：获客内容应该看什么指标？

## 十三、复习卡片

**Q：这套系统最核心的资产是什么？**  
A：自己的业务知识、客户语料、案例、方法 SOP 和不断更新的判断规则。

**Q：为什么不能只堆资料？**  
A：资料没有主题、来源、应用和淘汰机制时，只会增加检索噪声。

**Q：什么任务最适合先自动化？**  
A：高频、重复、标准明确、风险低、结果可抽查的任务，如录音整理和格式检查。

**Q：为什么人工改稿必须回写？**  
A：否则 AI 不知道你为什么改，下次还会重复同样的错误。

**Q：Skill 和 Agent 的区别是什么？**  
A：Skill 是可执行 SOP；Agent 是带触发、数据来源、回传和边界的运行方式。

**Q：何时可以考虑全自动发布？**  
A：在流程长期稳定、低风险、初稿几乎无需修改、审批与回滚机制完善之后；多数个人品牌内容仍建议保留人工审核。

## 最终学习重点

如果只记住五句话：

1. 不要追求 AI 一次写好，要建立能反复变好的系统。
2. 客户问题、真实案例和人工修改，是最有价值的第一方数据。
3. 知识库必须能进、能用、能追溯、能淘汰。
4. Skill 固化流程，Agent 负责触发和调度，人负责关键判断。
5. 先跑通一个小闭环，再自动化；系统不是一次搭完，而是在真实使用中长出来的。

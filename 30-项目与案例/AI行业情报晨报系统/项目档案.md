# AI行业情报晨报系统项目档案

> [!warning] 当前状态
> 旧项目页标记为 `active`，但Vault内最近晨报为2026-07-18，相关自动化在2026-08-16复盘中仍有浏览器覆盖缺口。本次只确认“系统设计资料存在”，不确认“当前正在稳定运行”。

## 一、项目目标

建立一套AI行业情报系统，持续发现国内外重要动态、热门应用、企业落地机会和重大风险，并把信息加工成：

- 国内外重点情报。
- 应用观察与实测建议。
- 企业机会与试点方向。
- 内容选题。
- 风险预警。
- 可复盘的预测和行动。

## 二、项目范围

- 模型、Agent、开源、产品、融资并购、企业采用和政策风险。
- 国际与国内信息分开筛选。
- 从原始来源追溯、反面证据、评分到行动加工的完整链路。
- 实时扫描、每日晨报、日终复核和周度复盘。

## 三、系统设计

核心加工链：

```text
发现信号
→ 原始来源追溯
→ 规范化
→ 去重聚类
→ 事实与观点分离
→ 可信度和影响评分
→ 反面证据检索
→ Top条目选择
→ 行动加工
→ 发布前质检
→ 持续跟踪与复盘
```

## 四、关键标准

- 重要事实必须有原始来源和明确日期。
- 传闻必须标记未确认，P2早期信号不能单独确认事实。
- 国内外Top条目不强行凑数。
- 供应商自述的增长、效率和客户数据必须标记来源属性。
- 找不到反面证据不等于没有风险。
- 无法访问的来源必须披露覆盖缺口。
- 不能生成具体动作的信息，相关度应降低。

## 五、原设计运行节奏

- 每12小时扫描高优先级源和异常信号。
- 每日完成候选采集、核验、评分和晨报发布。
- 每日18:00补充重大变化和预测状态。
- 每周一形成趋势、误判和行动复盘。

该节奏是设计目标，不是本次核验的当前事实。

## 六、原设计验收指标

- 晨报准时发布率不低于95%。
- Top条目原始来源覆盖率100%。
- A、B级条目独立验证率不低于80%。
- 旧闻误报和重复事件率低于5%。
- 预测按期复盘率100%。
- 每周至少完成一次高优先级应用实测、一个企业试点方案和三个实际使用的内容选题。

这些是目标指标，Vault内尚未形成连续30天验证证据。

## 七、当前已知证据

- 系统总览、模板、评分表、监测词表和自动运行规则存在。
- Vault内保存一份2026-07-18正式晨报。
- 存在情报评分和应用观察CSV底表。
- 2026-08-16 Codex复盘记录了Chrome控制端到端测试及一次对标雷达覆盖缺口，但这不能证明晨报系统持续稳定运行。

## 八、待核验

- 当前自动化是否仍绑定正确任务和时间表。
- 2026-07-18之后是否在其他目录或飞书存在晨报成品。
- 浏览器、来源覆盖和飞书送达的最新状态。
- 评分CSV是否持续更新。
- 30天指标是否有真实统计记录。
- 项目继续运行、暂停还是已由其他系统替代。

## 九、可沉淀知识和Skill

- 情报来源分级方法。
- 事实、企业自述、媒体判断和系统推演的分离方法。
- 情报去重与事件聚类SOP。
- 反面证据检索SOP。
- 情报评分与行动加工Skill。
- 自动化四层验收：调度绑定、浏览器控制、页面读取、消息回执。

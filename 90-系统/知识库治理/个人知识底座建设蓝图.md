# 个人知识底座建设蓝图

> [!important] 定位
> 这套知识库不是单一项目工作台，也不是文件收藏夹。它是面向长期积累、个人使用和 AI 调用的个人知识底座：以个人与业务主档案为上下文，以资料源为证据，以可复用知识为核心，以项目与案例为验证，以 SOP 和 Skill 为能力输出。

## 一、建设目标

知识库建成后，应同时满足五个目标：

1. 人打开后能迅速判断去哪里找，不依赖记忆复杂路径。
2. AI 能根据统一入口、类型、主题、摘要和可信状态检索内容。
3. 音频、逐字稿、图片、PPT、PDF、Word 等资料能被发现、保存并转成可搜索文本。
4. 原始资料可以逐步提炼为知识，并在项目中获得验证。
5. 成熟知识可以固化为 SOP、模板或可执行 Skill。

## 二、最高治理原则

### 1. 唯一真实来源

- `个人与业务主档案` 是关于个人、业务、偏好和长期方向的唯一真实来源。
- `Codex 长期记忆` 是主档案的压缩执行版，不与主档案并列维护事实。
- `每日复盘` 只是变化日志和候选记录，不是长期事实库。

### 2. 内容按性质组织，不按使用场景争抢文件夹

同一内容可能同时服务学习、工作和创作，因此不再依赖多层领域目录。文件所在层由内容性质决定，主题归属由 `topics` 属性表达。

### 3. 原始资料不等于知识

- 音频、逐字稿、PPT、图片和课程稿属于资料源。
- 能完整回答一个问题、解决一类任务且可复用的内容才进入知识层。
- 在真实项目中得到验证的方法，才适合升级为 SOP 或 Skill。

### 4. 限制可见入口，不强行限制物理文件数量

人日常只使用少数稳定入口。附件、索引、运行状态和历史版本留在后台；不能为了减少文件数，把所有内容塞进难以检索的巨型文档。

### 5. 文件夹层级保持浅

- 顶层按知识性质划分。
- 普通内容不再建立主题子文件夹。
- 单个项目最多使用一层项目文件夹，不继续按阶段、格式和状态嵌套。
- 附件多时只使用一个统一附件位置，不再分音频、图片、PPT等子目录。

## 四、六类知识对象

| 类型 | 回答的问题 | 典型内容 | 权威程度 |
| --- | --- | --- | --- |
| `context` | 我是谁、当前做什么、有哪些边界 | 个人与业务主档案 | 最高，当前任务说明可覆盖 |
| `knowledge` | 已经知道什么、为什么 | 方法论、判断、框架、已验证结论 | 高 |
| `project` | 做过什么、怎样验证、结果如何 | 项目、案例、复盘、实验 | 中高，提供实践证据 |
| `source` | 原话和原始证据在哪里 | 逐字稿、音频、PPT、PDF、图片 | 原始证据，不自动等于结论 |
| `skill` | 怎样稳定执行 | SOP、清单、模板、Skill规范 | 高，需标记测试状态 |
| `system` | 知识库怎样运行 | 收件、索引、日志、维护规则 | 仅系统维护时读取 |

## 五、知识生长链路

```mermaid
flowchart LR
    A[原始资料] --> B[转写 OCR 文本提取]
    B --> C[结构化资料记录]
    C --> D[提炼可复用知识]
    D --> E[项目与案例验证]
    E --> F[SOP与模板]
    F --> G[Skill候选]
    G --> H[测试与安装]
```

### 升级条件

#### 资料源进入知识层

至少满足一项：

- 能解决未来会再次出现的问题。
- 能影响判断或决策。
- 能指导一类具体行动。
- 能支持业务交付或内容生产。
- 能纠正过去的错误认知。

#### 知识进入 SOP 或 Skill 层

同时满足：

- 执行目标明确。
- 输入和输出可定义。
- 步骤可以重复。
- 成功标准可以检查。
- 风险和禁止事项可以表达。
- 已有一次以上真实使用或测试证据。

## 六、人类入口与 AI 入口

### 人类入口：知识库总览

总览只展示：

- 个人与业务主档案
- 知识
- 项目与案例
- 资料源
- 技能与SOP
- 待整理资料
- 待验证知识
- 待测试技能

系统日志、附件仓和历史版本默认不进入日常首页。

### AI入口：AI读取说明

AI 应按问题类型查询：

1. 涉及个人、业务定位和偏好：先查 `context`。
2. 涉及方法、判断和概念：先查 `knowledge`。
3. 涉及真实经历、结果和证据：查 `project`。
4. 涉及原话、逐字稿和原始材料：查 `source`。
5. 涉及具体执行步骤：优先查 `skill`。

### 冲突优先级

1. 当前任务中用户的明确说明。
2. 个人与业务主档案中最新、已确认的内容。
3. 已验证知识和已测试 Skill。
4. 已完成项目与案例。
5. Codex 长期记忆。
6. 结构化资料和原始资料。
7. 每日复盘、临时记录和历史归档。

## 七、统一属性

所有进入新体系的 Markdown 使用最小字段，不继续扩展多套状态词：

```yaml
---
title: 文件标题
type: context | knowledge | project | source | skill | system
topics:
  - 主题一
status: raw | reviewed | verified | outdated | archived
summary: 一句话说明这份内容解决什么问题
source:
  - 来源线索
updated: 2026-08-22
related: []
---
```

### 字段规则

- `type` 只表示内容性质。
- `topics` 表示主题，可以多选，不通过多层文件夹表达。
- `status` 表示成熟度和可信状态，不混入“第一版”“待启动”等项目进度。
- `summary` 必须让人和 AI 在不打开全文时判断是否相关。
- `source` 保存来源线索；没有来源的推断必须明确标注。
- `updated` 用于识别可能过期的内容。

## 八、命名规则

### 知识

用问题、方法或判断命名：

- `企业AI入企为什么先做诊断.md`
- `单岗位AI试点选择方法.md`
- `长逐字稿整理方法.md`

不使用：

- `新建文档.md`
- `未命名.md`
- `学习笔记1.md`
- `某某课程笔记.md` 作为长期知识标题

### 资料源

使用“日期-类型-主题”：

- `2026-08-22-访谈-制造企业AI需求.md`
- `2026-08-22-课程-企业知识库搭建.md`

### 项目与案例

使用真实项目名称，不把阶段写进文件夹名。阶段放在项目档案属性或正文中。

### Skill与SOP

使用动宾结构：

- `整理长逐字稿.md`
- `诊断企业AI场景.md`
- `研究对标账号.md`

## 十、每日资料监控

每日监控不是只检查“有没有新文件”，而是监控五个环节：

| 环节 | 完成条件 |
| --- | --- |
| 已保存 | 原始文件已复制或建立可靠引用，来源未被删除 |
| 可搜索 | 音频有逐字稿，图片有 OCR/说明，PPT/PDF/Word 已提取文本 |
| 已归类 | 已确定类型、主题和关联项目；不确定项进入待确认 |
| 已提炼 | 已判断是否形成知识，不能自动把原始材料升级为结论 |
| 可转Skill | 已评估能否形成 SOP 或 Skill 候选 |

### 扫描规则

- 从上次成功运行时间扫描到本次运行时间，不按自然日截断。
- 优先检查新项目目录，再检查 Desktop、Documents、Downloads 和指定录音/素材目录。
- 原始文件只复制或引用，不自动移动或删除。
- 使用文件哈希判断完全重复；同名不同内容不自动覆盖。
- 同一次课程、访谈或会议的音频、逐字稿、PPT和图片聚合成一个资料记录。
- 高可信归属可自动处理；中低可信进入待确认。

### 必须支持的格式

- 文本与办公：`.md`、`.txt`、`.docx`、`.pdf`、`.pptx`、`.xlsx`、`.csv`
- 音频：`.mp3`、`.m4a`、`.wav`、`.aac`、`.flac`
- 图片：`.jpg`、`.jpeg`、`.png`、`.webp`、`.heic`

### 当前实现状态

收件脚本已支持常见办公文件、文本、最终图片和音频；视频及大于100MB的文件只登记来源，不自动复制。日常只更新一个持续使用的[[00-知识库入口/待整理资料|待整理资料]]页面，状态和历史运行记录留在系统区。转写、OCR、资料聚合和知识提炼仍属于后续人工或专项处理，不由收件动作冒充完成。

## 十一、大文件与同步

- Markdown、结构化文本和索引是 AI 检索的核心。
- 大音频、视频和高分辨率图片不应无条件进入 Git 历史。
- 原始大文件可保存在 Vault 内独立资料仓，但需另行决定同步方式、容量上限和备份方式。
- 无论物理文件放在哪里，资料源记录必须提供稳定路径、摘要和可搜索文本。

在确认大文件同步方案前，不批量复制音频和视频进当前 Git 仓库。

## 十二、维护节奏

### 每日

- 扫描新资料。
- 检查是否可搜索。
- 提出归属建议。
- 更新待整理状态。

### 每周

- 处理待确认资料。
- 提炼高价值知识候选。
- 检查断链、孤立笔记和完全重复。
- 评估 Skill 候选。

### 每月

- 复核可能过期的知识。
- 检查项目是否应转案例或归档。
- 检查 Skill 真实安装路径、版本和测试状态。
- 复核个人与业务主档案是否需要更新。

## 十三、迁移阶段

> [!success] 执行状态
> 阶段一至阶段五的结构迁移、备份、索引、链接修复、旧结构归档和基础收件改造已于2026-08-22完成。详细结果见[[90-系统/知识库治理/个人知识底座迁移清单|迁移记录]]。

### 阶段一：蓝图和盘点

- 建立本蓝图。
- 建立现有资料迁移清单。
- 接入旧总首页。
- 不移动、不合并、不删除旧文件。

### 阶段二：小范围试迁移

选择能够覆盖全部类型的一组内容：

1. 个人与业务主档案。
2. 一份课程或长逐字稿资料源。
3. 一份可复用知识。
4. 一个真实项目或内部项目。
5. 一个 SOP 或 Skill 候选。

验证人能否快速找到、AI能否准确区分资料与结论、链接是否可靠。

### 阶段三：分批迁移

按“个人与业务 → 企业AI核心知识 → 项目案例 → 课程资料 → 模板与Skill → 其他内容”推进。每批迁移前建立恢复备份，迁移后核验链接和索引。

### 阶段四：收件自动化改造

扩展音频和图片支持，改为持续收件台账，加入文本提取、资料聚合、知识候选和 Skill 候选状态。

### 阶段五：旧结构归档

只有在新入口、检索和链接验证通过后，才将旧导航和已替代文件移入归档。删除任何重复内容前必须单独核验并备份。

## 十四、完成标准

知识底座不是“文件已搬完”就完成。至少要满足：

- 人从总入口不超过三次点击能找到目标内容。
- AI 能根据 `type`、`topics`、`summary` 和状态定位相关笔记。
- 原始资料与提炼结论有可追溯链接。
- 个人主档案、Codex执行记忆和每日复盘不存在权威冲突。
- 新音频、逐字稿、图片、PPT等资料不会漏收，并能看到处理状态。
- 已验证方法可以找到对应项目证据和来源资料。
- 正式 Skill 可以找到来源知识、测试记录和真实运行位置。

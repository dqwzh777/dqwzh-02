## 恢复顺序

1. 用系统Python创建 `/Users/mac/.codex/runtime/second-brain` 虚拟环境。
2. 安装依赖清单，并用 `imageio-ffmpeg`提供的本地二进制建立 `bin/ffmpeg`链接。
3. 将主管线和OCR脚本部署到Codex Skill运行目录。
4. 将LaunchAgent配置部署到用户LaunchAgents并重新加载。
5. 下载并校验Whisper small模型。
6. 分别用一张含中文的图片和一段已知内容的音频测试，不能只检查命令存在。
7. 运行主管线 `run`，确认[[90-系统/收件系统/最近运行报告|最近运行报告]]显示成功。

## 启用 Windows 移动端投递

在 macOS 主机终端运行一次：

```zsh
zsh "/Users/mac/Documents/Obsidian Vault/90-系统/收件系统/启用移动端投递-macOS.sh"
```

该脚本只允许快进拉取 `main`，随后重载每日22:20的 LaunchAgent。之后主管线会只读拉取 GitHub `windows-inbox` 分支的 `00-知识库入口/移动端投递/`，复制到主机的 `知识库投递/Windows移动端` 后进入既有收件流程；它不会把该分支合并到 `main`。

## 失败判定

- 没有模型、OCR脚本或ffmpeg：对应资料保留原件并进入失败/待处理状态。
- 后台调度失败：22:30的Codex总管读取运行状态并尝试恢复。
- Git远端领先、发生分叉或出现敏感文件名：停止自动同步，不强推、不自动合并。

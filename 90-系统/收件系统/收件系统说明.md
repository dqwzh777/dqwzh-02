# 收件系统说明

## 人看到的入口

日常只看[[00-知识库入口/待整理资料|待整理资料]]。日期收件记录、状态JSON和运行细节留在本目录后台，不占据知识库首页。

需要主动交给知识库的资料，放入电脑上的 `/Users/mac/Documents/知识库投递/`。这里属于高可信投递区；ChatGPT 导出、录音与逐字稿、其他资料分别放入其三个入口，但进入 Obsidian 后仍统一由一张待整理清单管理。

## 监控范围

- Markdown、TXT和逐字稿。
- Word、PDF、PPT、Excel和CSV。
- JPG、PNG、WEBP等图片。
- MP3、M4A、WAV、AAC等音频。
- MP4、MOV等视频只登记线索；大文件存储方式另行确认。

## 处理链路

```text
发现新增资料
→ 按上次成功运行时间滚动扫描
→ 去重和保留原件
→ 登记到待整理资料
→ 转写/OCR/文本提取
→ 进入资料源
→ 提炼知识
→ 项目验证
→ SOP或Skill
```

## 自动收录判断

| 来源或状态 | 默认动作 |
| --- | --- |
| `知识库投递`、Codex `outputs`、明确标注最终版/报告/方案/逐字稿的资料 | 去重后自动收件 |
| Desktop、Documents、Downloads 中含义不明确的资料 | 只登记为“待确认”，不复制 |
| Word、PDF、PPT、Excel、Markdown、TXT、CSV | 生成可搜索 Markdown 资料页 |
| 图片 | 用macOS Vision自动OCR，结果标记“已OCR待复核”；识别失败才保留“待OCR” |
| 音频 | 用本地Whisper small自动转写，结果标记“已转写待复核”；识别失败才保留“待转写” |
| 视频或超过100MB的文件 | 只登记原路径，不复制 |
| 源码仓库、凭据、安装包、缓存、QA、渲染预览 | 跳过 |

`收件队列.json` 是机器状态，[[00-知识库入口/待整理资料|待整理资料]]是人的工作清单。原始附件、可搜索资料页和知识笔记是三个不同阶段，不能混为一层。

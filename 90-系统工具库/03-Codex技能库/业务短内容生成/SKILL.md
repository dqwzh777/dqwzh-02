> 用途:把业务问题、客户原话、案例证据、产品卖点写成短视频、图文、朋友圈或私域承接内容。

## 5 种使用模式

| 模式 | 适合输入 | 输出方向 |
|---|---|---|
| 客户问题型 | "客户总问 XXX" | 教育客户、解释认知 |
| 销售异议型 | "客户嫌贵/不信/犹豫" | 处理异议、降低决策阻力 |
| 案例证据型 | "这个客户前后变化" | 建立信任、证明结果 |
| 产品服务型 | "介绍这个服务" | 讲清价值、边界和适合人群 |
| 课程转化型 | "这节课要预热" | 引出课程/咨询/私域承接 |

## 写作结构

### 1. 第一口先对人说

开头不要从概念说,先点中具体人和具体场景:

- "如果你是实体老板,每天都在重复回答同一个问题..."
- "很多客户不是不想买,是他没看见你能解决哪一步..."
- "你以为是员工不会用 AI,其实是公司没有把资料变成流程..."

### 2. 中间只讲一件事

短内容只解决一个问题:

- 一个客户卡点。
- 一个判断。
- 一个案例。
- 一个动作。
- 一个误区。

### 3. 结尾要有承接

根据用途选择结尾:

| 用途 | 结尾 |
|---|---|
| 获客 | 引导评论/私信具体问题 |
| 私域 | 引导看案例/表格/课程包 |
| 销售 | 引出诊断或下一步沟通 |
| 课程 | 引出课上会带大家做什么 |

## 输出格式

```markdown
# [标题]

- 来源:
- 应用:短视频 / 图文 / 朋友圈 / 私域承接 / 销售话术
- 状态:可直接用 / 待补细节 / 待核实
- 缺口:

## 正文
[可直接发布的短内容]

## 可改成口播
[更口语、更短句的版本]

## 承接句
[评论/私信/课程/咨询/资料包承接]

## 使用建议
- 适合平台:
- 适合人群:
- 发布前要核实:
```

---

## 质量红线

- 不写没有来源的案例。
- 不承诺具体结果。
- 不把老板/IP 写成流量网红口吻。
- 不为了互动牺牲信任。
- 不把业务内容写成泛泛鸡汤。

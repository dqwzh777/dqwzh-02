# 产品/服务分析与定位

> 用途:把一个产品、服务、课程、咨询方案或企业 AI 交付,拆清楚"卖给谁、解决什么、凭什么信、怎么承接"。
> 核心:不是单纯上架前分析,而是业务表达和成交承接的定位底稿。

## 分析流程

### 1. 先定业务对象

```markdown
- 名称:
- 类型:产品 / 服务 / 课程 / 咨询 / 企业方案 / 交付包
- 当前阶段:想法 / 已售卖 / 待优化 / 待标准化
- 主要价格/交付周期:
- 目前最大卡点:
```

### 2. 拆客户

不要只写"适合老板",要拆到真实场景:

- 他是谁?
- 他现在卡在哪?
- 他为什么现在要解决?
- 他试过什么,为什么没解决?
- 他为什么会相信你?
- 他为什么会犹豫?

### 3. 拆问题

| 层级 | 问题 |
|---|---|
| 表层问题 | 客户嘴上说的问题 |
| 真实问题 | 影响成交/效率/结果的真实原因 |
| 系统问题 | 背后的资料、流程、团队、信任、复盘问题 |

### 4. 拆价值

用客户语言表达,不要只写功能:

```markdown
- 客户买的不是:
- 客户真正想要:
- 你帮他减少:
- 你帮他增加:
- 你帮他看清:
- 你帮他跑通:
```

### 5. 拆证据

| 证据类型 | 有没有 |
|---|---|
| 客户原话 |  |
| 案例前后变化 |  |
| 交付过程截图/记录 |  |
| 现场故事 |  |
| 方法论框架 |  |
| 团队/公司背书 |  |

没有证据就标缺口,不要编。

### 6. 拆边界

```markdown
- 适合谁:
- 不适合谁:
- 能解决什么:
- 不能承诺什么:
- 客户必须配合什么:
- 交付前需要准备什么:
```

### 7. 拆承接

| 场景 | 该怎么用 |
|---|---|
| 内容 | 讲客户问题、误区、案例 |
| 私域 | 解释适合谁、不适合谁 |
| 销售 | 处理异议、证明价值 |
| 课程 | 变成课堂练习和案例 |
| 企业落地 | 变成 SOP、资料表、交付清单 |

## 课堂讲法

这节课不要讲成"产品卖点提炼",要讲成:

> 产品不是你有什么,产品是客户相信你能帮他解决哪一步。

现场练习:让学员选一个自己的产品/服务,先写"客户买的不是 X,客户真正想要 Y",再补一条证据和一个边界。

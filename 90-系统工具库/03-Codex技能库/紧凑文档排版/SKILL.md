# 紧凑文档排版

## 执行顺序

1. 读取原文档，识别标题层级、正文、表格、图片、提示框和分页结构。
2. 创建或编辑 DOCX 时同时使用可用的 Word 文档处理 Skill；生成或核验 PDF 时同时使用可用的 PDF Skill，并遵守其渲染检查流程。
3. 完整读取 [references/layout-standard.md](references/layout-standard.md)，将其中规则作为默认排版规范。
4. 保留原文内容和逻辑；除非用户授权，不擅自删减、改写或补造信息。
5. 先应用页面、字体、标题、段落、表格、图片、页眉页脚等基础样式，再处理分页。
6. 逐页压缩无意义留白，同时守住可读性下限。优先调整段前段后、标题间距、图片尺寸、表格列宽和分页位置，不靠异常缩小字号或行距硬塞内容。
7. 强制检查每张表格：表题、表头、主体及必要说明必须完整保留在同一页。放不下时按“精简内容 → 调整列宽 → 合理缩小字号 → 横向页面 → 拆成多个独立表格”的顺序处理。
8. 输出 DOCX 后渲染为 PDF 或页面预览，逐页目视检查；发现留白过多、跨页、截断、重叠、孤行或版式失衡时，继续调整直至通过。
9. 用户要求正式交付且未另行指定时，交付 Word 与 PDF 两种格式。

## 决策原则

- 将“紧凑”理解为提高有效信息密度，而不是牺牲阅读体验。
- 封面、章节首页或用户明确要求独立成页的内容可以保留设计留白；其他页面不得出现大面积无意义留白。
- 不让标题悬在页底，不让单行正文孤立到下一页，不让图片与图注分离。
- 不允许表格跨页，不允许表头与表身分离，不允许单元格或表格行被分页截断。
- 大表优先拆分并为每个子表补充明确标题和完整表头；确需横向页面时只对相关页面设置横向，随后恢复纵向。
- 用户提供品牌色、Logo、模板或既有文档时，以用户素材为最高优先级；未提供时使用规范中的默认商务配色。

## 交付检查

交付前确认：

- 标题层级、编号、字体、字号、行距和颜色统一。
- 页面紧凑均衡，没有异常空白页或大面积留白。
- 所有表格完整单页展示，内容可读且未截断。
- 图片比例正确，图注未分离，图片不超出版心。
- 页眉、页脚、页码及封面页码规则正确。
- DOCX 与 PDF 的分页和视觉结果一致；PDF 逐页渲染检查通过。
- 文件可正常打开，最终交付路径清晰。

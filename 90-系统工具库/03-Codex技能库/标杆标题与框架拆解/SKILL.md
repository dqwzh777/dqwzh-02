# 标杆标题与框架拆解

> 用途:借助对标库产出标题、第一口、文章/视频/课程框架候选。
> 核心:不替用户定稿,只给足够多的高质量选择,再让用户按自己的判断选。

## 用前准备

先准备 `对标表达库.md`。里面不一定都是账号,也可以是:

- 同行高效标题。
- 课程开场。
- 销售页标题。
- 私域转化话术。
- 短视频第一句话。
- 你自己历史上效果好的内容。

每条最好标清:

```markdown
- 来源:
- 适合学什么:
- 不适合照搬什么:
- 典型标题/第一口:
- 背后的客户问题:
```

## 三种模式

| 模式 | 触发词 | 输出 |
|---|---|---|
| A 起标题 | 起标题、标题候选、取个标题 | 10-20 个标题候选 |
| B 做第一口 | 开头怎么说、第一句话、短视频开头 | 10 个第一口候选 |
| C 搭框架 | 搭框架、写作思路、课程段落怎么讲 | 3-8 套框架候选 |

触发不清楚时,先问一句:你要标题、第一口,还是整体框架?

## 工作流

### Step 1 明确输入

至少确认:

- 主题是什么?
- 核心观点是什么?
- 要给谁看?
- 最后要承接到哪里:关注、评论、私信、课程、咨询、成交、内部培训?

### Step 2 先读资产

| 需要判断 | 先读 |
|---|---|
| 用户身份、风格、禁区 | **老板与企业说明书** |
| 承接产品/服务 | **产品服务库** |
| 客户真实问题 | **客户问题库** |
| 案例证据 | **案例证据库** |
| 对标风格 | `对标表达库.md` |

### Step 3 多标杆产出

每个候选必须标注:

- 代入对象。
- 用了什么表达机制。
- 适合哪类客户。
- 风险点。
- 需要补什么证据。

### Step 4 推荐,但不替用户决定

最后给:

- 最稳妥 TOP 3。
- 最有冲击力 TOP 3。
- 最适合销售承接 TOP 3。

并提醒:最终标题/框架要由用户结合真实业务和个人表达定稿。

## 输出格式

```markdown
# 标题/框架候选

## 输入确认
- 主题:
- 核心观点:
- 目标人群:
- 承接动作:

## 候选
| 候选 | 代入对象 | 表达机制 | 适合场景 | 风险点 |
|---|---|---|---|---|
|  |  |  |  |  |

## 推荐
- 最稳:
- 最有记忆点:
- 最适合成交承接:

## 需要补的资料
- ...
```

---

## 关键约束

- 不凭空编对标账号风格。
- 不为了冲击力牺牲可信度。
- 不生成和用户业务无关的标题党。
- 不直接照搬对标原句。
- 不写完整正文,只做标题、第一口或框架候选。

## 推荐下一步

| 当发现… | 推荐 |
|---|---|
| 选定后要写短内容 | → **业务短内容生成** |
| 要拆具体对标 | → **对标表达拆解与迁移** |
| 要检查标题是否贴合业务 | → **内容诊断** |

## 课堂讲法

这节课可以讲成:

> 标题不是文字游戏,标题是你选择从哪个客户问题进入。

课堂练习:同一个选题,让 AI 分别从"客户痛点、信任证据、反常识、成交承接"四个方向出标题,让学员感受不同标题背后的业务入口不同。

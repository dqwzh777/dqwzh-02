# AI读取说明

## 一、先判断问题类型

| 问题 | 优先读取 |
| --- | --- |
| 用户是谁、业务方向、偏好和边界 | `10-个人与业务` |
| 方法、概念、判断和框架 | `20-知识` |
| 做过什么、结果如何、有什么证据 | `30-项目与案例` |
| 原话、课程、逐字稿、PPT和原始材料 | `40-资料源` |
| 具体怎样执行、输出和验收 | `50-技能与SOP` |
| 知识库、自动化和Codex怎样运行 | `90-系统` |

## 二、可信度顺序

1. 当前任务中用户的明确说明。
2. [[10-个人与业务/个人与业务主档案|个人与业务主档案]]中最新、已确认的内容。
3. `status: verified` 的知识和已经测试的Skill。
4. 有结果与验收证据的项目和案例。
5. Codex长期记忆。
6. `status: reviewed` 的知识和结构化资料。
7. `status: raw` 的原始资料。
8. 每日复盘、临时记录、历史归档。

## 三、必须区分的内容

- 资料源中的讲者观点不自动代表用户观点。
- AI生成摘要不等于完整逐字稿。
- 项目设计不等于项目已稳定运行。
- 供应商或讲者自述数据不等于已经核验的事实。
- `reviewed` 表示内容已经整理，不等于已经通过真实项目验证。
- `verified` 必须能够找到项目、案例、数据或其他明确证据。

## 四、读取和回答规则

- 优先读取笔记的 `summary`、`type`、`topics`、`status`、`source` 和 `updated`。
- 结论需要来源时，沿“知识 → 项目或资料源”链接追溯。
- 价格、客户、项目进度、软件能力、政策和外部链接等易变信息必须在当前任务重新核验。
- 找不到证据时写明“待核验”，不能用推断补成事实。
- 旧文件与新文件冲突时，先按照可信度顺序判断；重大冲突应提示用户。
- 不读取或输出密码、密钥、令牌、Cookie、验证码及不必要的敏感个人信息。
- 客户与合作方材料默认脱敏。
- Office、PDF、文本等附件优先读取其对应的 `40-资料源/待整理资料页`，再按需追溯原始附件。
- `待转写`、`待OCR`、`待转换`只证明文件存在，不证明AI已经读取了其中内容。
- `待确认`资料未通过收录判断，默认不把文件名推断成事实。

## 五、默认排除

普通业务问答默认不读取：

- `99-归档`中的旧导航和重复版本。
- 每日收件运行日志。
- Codex每日复盘全文。
- 与问题无关的原始附件。
- 没有可复用价值的临时操作记录。

只有在追溯历史、排查系统或核对来源时才进入这些区域。

## 六、知识升级规则

```text
资料源
→ 结构化资料
→ 可复用知识
→ 项目验证
→ SOP
→ Skill候选
→ 实测
→ 正式Skill
```

AI不能跳过验证过程，直接把一段课程观点安装为正式Skill。

## 七、当前运行边界

- 全量结构迁移已于2026-08-22完成，旧结构只在`99-归档/旧结构-20260822/`中保留，不参与默认检索。
- 晨报系统和个人AI工作台的项目资料已入库，但其当前真实运行状态仍需现场核验。
- 每日收件已支持常见音频、图片、PPT、PDF、Word等格式；视频和大于100MB的文件只登记来源，不自动复制。
- 文本、Word、PDF、PPT和Excel会自动形成可搜索资料页；当前环境没有可靠的本地语音转写和图片OCR运行时，因此音频与图片分别进入“待转写”和“待OCR”。
- 收件自动化负责发现、去重、登记和支持格式的文本提取；周日只生成带来源的知识候选，不自动安装Skill。
- [[00-知识库入口/待整理资料|待整理资料]]中的内容尚未升级为长期知识。
